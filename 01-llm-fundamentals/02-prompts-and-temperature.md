## 1. What is a prompt?

A prompt is the input or set of instructions provided to an LLM to guide
the response it generates.

A prompt can include: - **Role:** What perspective or behaviour should
the model adopt? - **Task / user request:** What should the model do? -
**Context:** What information does the model need? - **Constraints:**
What rules or limitations should it follow? - **Output format:** How
should the response be presented?

A clearer and more relevant prompt can help the model produce a more
useful response.

**My answer:** A prompt is a set of instructions using which a model
generates its output. The better the prompt, the better the result. A
prompt can have a role, user request, context, constraints, and output.

**Refined understanding:** A prompt is not limited to instructions. It
can also include questions, examples, reference data, and conversation
context. Prompt quality matters, but a better prompt does not guarantee
a correct answer.

## 2. System vs. user vs. assistant messages

LLM applications commonly structure conversations using message roles.

  ----------------------------------------------------------------------------------------------------------------------------------
  Role                    Purpose                 Example
  ----------------------- ----------------------- ----------------------------------------------------------------------------------
  System                  Sets high-level         `Act as a senior developer.`
                          behaviour and           
                          instructions for the    
                          model.                  

  User                    Contains the user's     `Explain JavaScript closures.`
                          request or input.       

  Assistant               Contains the model's    `A closure is a function that retains access to variables from its outer scope.`
                          response.               
  ----------------------------------------------------------------------------------------------------------------------------------

**My answer:** - System: How the model should behave, for example, "Act
as a senior developer." - User: The task that needs to be performed. -
Assistant: The output generated by the model, for example, "A closure is
a function that..."

**Refined understanding:** These roles identify who is speaking and help
structure the conversation. Some APIs also support other roles or
message types, such as developer instructions and tool messages. We'll
explore those later.

## 3. What is prompt engineering?

Prompt engineering is the process of improving, designing, and
structuring prompts to get more useful results from an LLM.

It can involve: - Giving the model a clear role. - Defining the task. -
Providing relevant context. - Adding constraints. - Specifying the
expected output. - Testing and refining the prompt based on the results.

**My answer:** Improving the quality, instructions, design, and overall
structure of a prompt to get better results from the model is called
prompt engineering. It includes role, user request, context,
constraints, and output.

**Refined understanding:** Prompt engineering is an iterative process:
design a prompt, test the response, identify what is missing or unclear,
and improve the prompt. A well-structured prompt can improve relevance
and consistency, but it cannot guarantee factual correctness.

## 4. What is temperature?

Temperature is a generation parameter that influences how an LLM selects
among possible next tokens.

In general: - **Lower temperature:** Responses tend to be more focused
and predictable. - **Higher temperature:** Responses tend to be more
varied and less predictable.

Temperature does not make a model more intelligent. It changes the
sampling behaviour during generation. The available range and exact
behaviour depend on the model and API.

**My answer:** Temperature is a generation parameter that controls how
the model selects among the next possible tokens.

**Refined understanding:** Temperature affects the probability
distribution used during token selection. Lower values generally favour
higher-probability tokens, while higher values generally allow more
variation.


### Experiment 2 --- Context-based prompt


``` text
Role: Senior JavaScript developer.

Task: Explain JavaScript closures.

Audience: Frontend developer with 2 years of experience.

Requirements:
1. Explain the concept.
2. Show a code example.
3. Explain how the code executes.
4. Mention one real-world use case.

Keep it practical and concise.
```
